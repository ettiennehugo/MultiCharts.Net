### Effect on the sandbox retests (result-run order)
Only ES / NQ futures and stock data are available, so in practice the futures changes show up on NQ:
1. **T-C1** changes NQ (and CL / 6E) trades in the 156 fallback files and in GX-armed studies. ES does not change.
2. **T-C3** changes NQ trades in the 35 literal-14 files it covers (the 3 batch-1 literal-14 files go through #149 instead), and turns every fallback into a loud failure.
3. **T-R2** changes which bars are roll bars on every futures run, ES included.

So NQ rows recorded before T-C1 are labelled **pre-T-C1**, and every futures row recorded before T-R2 / T-C3 is labelled **pre-migration**. To avoid running the batches three times, the counted re-run is done once, after T-C1, T-C3 and T-R2 have all merged; interim runs are smoke tests only. ES-only rows recorded before T-R2 still need the T-R2 re-run. Stock / ETF rows re-run once their T-S1 rows exist.
