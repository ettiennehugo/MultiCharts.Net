## 2. Tasks in order

The engine tasks come first. Each task is a small PR on a feature branch against `main`, merged by Ettienne. Rebase after #144 / #145 / #147 merge: they touch the same sandbox files but none of these lines (verified on `f7b2c56`).

- **T-C1 cost rows** (engine, `_InstrumentProfile`): add `Future:NQ` 948, `Future:CL` 1472, `Future:6E` 1117; update `costSource`; InstrumentTests floors NQ 19, CL 15, 6E 18. Canon / profile hashes for NQ / CL / 6E change; ES / MES pins do not. *Depends on nothing.* **T-C1b** (later): MNQ 172 / GC 1502 rows and the ZN unit change, only after Ettienne approves the PROPOSED floors.
- **T-C2 loud failure** (engine): one host check, e.g. `requireCostFloor(ds)`. It logs an Error and throws `unknown-field:cost` when a floor-using study's stream has `costFloorTicks < 0`. `gxFloorTicks()` calls it instead of returning 0. Off-MC tests: NQ / CL / 6E / ES / MES give a floor; GC with no row throws; a stock stream follows whatever Ettienne decides on m-instr §9.1 rule 5 (PROPOSED). *Depends on T-C1* (otherwise NQ / CL / 6E runs would stop).
- **T-R1 roll journal** (engine, `_CustomSignal` + `_RollDetector`): feed `RollGapCalibrator` in Table mode; on a Table roll bar print `ROLL table splice(...) gapPts() atr20() gapAtr() k() confirmed()`; print the off-table `ROLL off-table gap(...)` Warning; add a protected `RollGapAtrK` (no `[Input]`; default **1.0, PROPOSED, pending owner approval**); add the empty-table loud failure, or auto-fill, per Ettienne's answer (m-instr §7.1 item 5). RollTests: the Table splice set unchanged, the journal fields, the off-table Warning, the empty-table behaviour. *Independent of T-C1/T-C2.*
- **T-R2 sandbox roll migration** (190 files + AV-08): `RollDetection = ERollDetection.Table` plus `fillProfileRollDates(<chart from-year>, <to-year>, "ROLL")` in StartCalc for futures streams (the non-futures `Off` line stays). AV-08 gets the fill too. Review the 19 files with no `ERollDetection` and the 13 Off-only files: if they trade futures across sessions, add Table; otherwise record why Off is right. SandboxCompile / RepoLint: a new check that no sandbox file uses `Series` or `SeriesOrTable`. *Depends on T-R1.*
- **T-C3 sandbox floor migration** (194 files): replace every literal 14 and every 1-tick / `return 1` fallback with the profile floor through the T-C2 check, so the floor is per market and a missing row fails loudly. Keep "widen, then skip, never shrink". SandboxCompile check: no `costFloorTicks = 14`, no `14 * tick`, no `int ticks = 1;` floor fallback. *Depends on T-C1 and T-C2.*
- **T-R4 / T-C4 evidence run** (Analyst, MiniPC, ≤ 2024-12-31 only): after T-R1, run @ES and @NQ 1m 2016-06…2024-12 and report the confirmed / unconfirmed table rolls, the off-table Warnings and the `gapAtr` distribution, so k can be set. After T-C3, re-run the affected sandbox batch-1 slots, because floors change on every non-ES root and stop changing silently.
- **Docs follow-up** (Analyst): `docs/engines-manual.md` §1.7 cost-floor pitfall (~L267: "14 ticks", "no floor yet") and App F Known issue 1; the GX spec's "ES 14, NQ 19" floor lines (after #146 merges, to avoid a conflict); PDF mirrors.

### Effect on the sandbox retests
T-C3 changes stop distances and therefore trade lists on every non-ES instrument. Files that used the 1-tick fallback already get 14 on ES, because ES has a profile floor, so ES does not change there; NQ / CL / 6E / GC / ZN do. T-R2 changes which bars are roll bars on every futures run. Batch results recorded before T-R2 / T-C3 are labelled **pre-migration** in the results CSV and must be re-run before they count.
