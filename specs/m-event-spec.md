## 0. Cross-cutting rules (inherited)

- **EV-0.1 Laziness (MFS §0.1, P3 §0.1).** The engine is an `internal sealed class` created in `StartCalc()` only when `EventConfig.enabled` is true, and is `null` otherwise. **No new `[Input]`s** on `_CustomSignal` or any of the 14 strategies on it. A disabled engine's accessors return neutral values (`false`, `NaN`, `EEventTier.None`, empty lists) and log one Warning (the `m_regimeQueryWarned` pattern).
- **EV-0.2 MC-free core.** All date rules, tables and lookups live in `_EventCalendar.Function.CS` inside `// <event-rules>` … `// </event-rules>` and `// <event-table>` … `// </event-table>`. They use no MultiCharts types, so `tests/EventTests/gen.sh` can extract and compile them (the `tests/CalendarTests` pattern).
- **EV-0.3 C# 7.3.** No switch expressions, `??=`, nullable reference types or ranges. No LINQ and no allocation on the per-bar path: lookups are binary searches over sorted arrays built once per year.
- **EV-0.4 Journal.** Facts go to `engineSink(ETraceLevel.Journal)` and are stamped with bar times (`yyyy-MM-dd HH:mm:ss`, chart TZ), never bar indexes. Per-bar detail goes to `Debug`. A `null` sink formats no string. Event instants in journal lines are printed in ET with the zone label (`08:30 ET`) next to the chart-TZ bar stamp.
- **EV-0.5 Built-ins first.** Time zones come from `TimeZoneInfo` via the existing `findTz`, `BarTimeZone`, `ToZone` and `resolveBarTimeZone`. Holidays and half days come from `_NyseHolidays.Rules` and `_CmeHolidays.Rules` (MC's Quote Manager holiday lists are not readable from code, so nothing new is invented here). Rolls come from `rollOn(1)` / `_RollDetector`. Trading days come from `tradingDayKey`.
- **EV-0.6 Config hash.** `EventConfig.Canon()` returns its fields in fixed order, plus a hash of the loaded table and CSV (EV-4.6), so the journal's per-run config hash identifies the calendar version (P3 §0.5).
- **EV-0.7 Recalc idempotence.** Every query is a pure function of (bar time, config, table). There is no state that a recalc could double-count.

## 2. Data model

- **EV-2.1 Record** (in `// <event-rules>`):
```csharp
public struct EventRec {
    public EEventKind kind; public EEventTier tier; public EEventFlags flags;  // Sep, Quad, Unscheduled, Scheduled, Delayed, Canceled, Csv, RuleOnly
    public DateTime etTime;        // ET wall clock (Kind=Unspecified); for spans, the start
    public DateTime etEnd;         // spans only (RollWeek); else == etTime
    public DateTime utc;           // derived once, EV-3.2
    public DateTime knownSinceUtc; // when the schedule for this instant was public (EV-5.1); MinValue = known well in advance
    public DateTime canceledSinceUtc; // MaxValue = never canceled (EV-5.3)
    public DateTime tradingDay;    // Globex trade date of the instant (EV-3.4)
    public string refPeriod;       // "2025-09" / "2026Q3"; "" for calendar items
    public string source;          // short source tag, e.g. "BLS-2025-lapse", "FED-20200315"
}
```
- **EV-2.2 Year cache.** `_EventCalendar.Year(int y)` builds a sorted `EventRec[]` for year y once: table + rules + corrections + CSV (EV-4). The engine keeps years y−1, y, y+1 (the `_Holidays` "current and previous year" rule, extended forwards for `NextEvent` across New Year).
- **EV-2.3 Sorting.** The cache is sorted by `utc`, then by tier descending. The day index is a `Dictionary<DateTime, int[]>` from trading day to record indexes, built with the year.

## 3. Time zones and DST

- **EV-3.1 Store ET wall time.** "08:30" means 08:30 America/New_York on that date, whether EST or EDT. Windows id `"Eastern Standard Time"` (the id `_CmeSessionClock` and `autoTradingDay` already use) goes through `findTz`.
- **EV-3.2 Derived UTC.** `utc = TimeZoneInfo.ConvertTimeToUtc(etTime, est)`. Release times are never inside the 02:00–03:00 transition hour. A record that is would be a table error: `Configure()` rejects it if `est.IsInvalidTime` or `IsAmbiguousTime` (no clamping).
- **EV-3.3 Bar comparison.** A bar's interval in UTC is `[barOpenUtc, barCloseUtc)`. `barCloseUtc` comes from `Bars.Time[0]` (MC stamps bars at their close) converted from `BarTimeZone` with the same `IsInvalidTime` guard as `ToZone`. `barOpenUtc = barCloseUtc − Resolution.Duration()` for time-based bars. For non-time bars it is the previous bar's close (**PROBE** the first bar of a session). The event "is in" the bar whose interval contains `utc`. So a 1m bar stamped 08:31 ET contains the 08:30:00 release, and the bar stamped 08:30 is the last pre-event bar. PROBE P-EV1: verify empirically that the 1m volume spike of 08:30 releases lands in the bar stamped 08:31 ET for dxFeed @ES in all three `RequestTimeZone` settings, including DST and mismatch weeks (test EV-8.11).
- **EV-3.4 Minutes are UTC differences.** `MinutesTo` and `MinutesSince` are `(utc − nowUtc).TotalMinutes`, never ET wall-clock subtraction. Across the DST weekend, Fri 2026-03-06 14:00 ET to Mon 03-09 08:30 ET is 3 × 1440 − 330 − 60 = 3930 minutes, not 3990 (test EV-8.3).
- **EV-3.5 Chart zones.** All three `RequestTimeZone` cases work through `resolveBarTimeZone`: Exchange (CME = Central), Local (the user's PC, which may observe no US DST, so the ET offset to local time changes on the US DST dates and the window must follow it), and GMT. US/EU DST mismatch weeks (March and late Oct–early Nov) are where a fixed offset would break. Tests EV-8.3 cover them. On a pre-2007 extension, Windows `TimeZoneInfo` historical adjustment rules must be confirmed (US DST rules changed in 2007).
- **EV-3.6 Trading day.** `tradingDay` = the Globex trade date of the first Globex session open at or after the instant, by `_CmeSessionClock` (an instant ≥ 18:00 ET on a session day maps to the next date; an instant in the 17:00–18:00 break, on a weekend or on a closed day maps to the date of the next session that opens). Sun 2020-03-15 17:00 ET → Mon 2020-03-16 (EV-8.5).
- **EV-3.7 Daily and weekly bars.** On a daily or weekly Data1 (or `DailyConfig` stream), instants mean nothing inside the bar. Only the day queries (EV-6.4/6.5) are valid. The window queries return `false` and log one Warning if `Resolution.Duration() ≥ 1 day`. A weekly bar's classification is the max over its trading days (`EventsInRange`).

## 4. Building the list (mirrors `_NyseHolidays` / `_CmeHolidays`)

The repo's pattern: date **rules** and a short **special-dates array** with a source comment per date, in a nested MC-free `Rules` class, generated per year, wrapped by a `_Holidays`-style host and tested in `tests/CalendarTests`. M-EVENT follows it.

- **EV-4.1 Rule-generated kinds** (`Rules.Generate(year)`): `Claims` (dates from the DOL archive (EV-1.8); the rule only generates beyond the archive), `IsmMfg`/`IsmSvc` (Nth business day with NYSE holidays from `_NyseHolidays.Rules`, plus `s_ismExceptions` (e.g. Mfg Jan 2026 → 01-05) for ISM-published moves, e.g. Services Jul 2026 → Mon 07-06), every §1.2 item, `EiaPetroleum` (Wednesday rule + `s_eiaExceptions` from the EIA schedule), and `HalfDay` from `_CmeHolidays.Rules`.
- **EV-4.2 Table kinds** (FOMC ×3, CPI, PPI, NFP, JOLTS, PCE, GDP ×3, Retail, Jackson Hole, Chair testimony): these have no reliable rule, so they go in a **generated in-code table**, `// <event-table>`: `static readonly long[] s_yyyymmddhhmm` plus a parallel `byte[] s_kind`, one pair per year (an `int` cannot hold 202610220830 > 2³¹), with a header comment giving the build script version, the fetch date and per-source SHA-256 of the pages fetched. The table is written by the script in EV-4.5, never by hand, and the repo diff is what Analyst 2 reviews.
- **EV-4.3 Corrections list** (`s_corrections`, in code, hand-maintained, every row with a source URL): past-dated changes to the scheduled calendar. Each row has (kind, refPeriod, originalEt or none, actualEt or Canceled, announcedEt, flag). See §5.
- **EV-4.4 CSV override / extension** (`EventConfig.csvPath`, empty = none). Columns: `action,kind,date_et,time_et,tier,flags,ref_period,announced_et,source`. `action` ∈ {`add`, `remove`, `retime`, `retier`}. `kind` may also be `Custom:<name>` (a free-form kind, tier required). Rules: (a) CSV rows apply after table, rules and corrections; (b) the file is read once in `Configure()` with no per-bar I/O; (c) any parse error fails `Configure()` with line number and text (report, never skip); (d) every applied row is flagged `Csv` and counted in the journal; (e) the file's SHA-256 goes into `Canon()`. A `retime` row with `announced_et` later than its original date is treated as an unscheduled change (EV-5.2). (f) `announced_et` is **required** for `add` and `retime` rows. A blank value is allowed only with flag `Scheduled` plus a `source` showing publication before the instant; otherwise `Configure()` fails.
- **EV-4.5 Build script** `tools/m-event/build_table.py` (outside MC; Python 3, stdlib + `requests`/`lxml`). Steps: (1) fetch the official pages per year (Fed `fomccalendars.htm` and `fomchistoricalYYYY.htm` via `fomc_historical_year.htm`; BLS `bls.gov/schedule/YYYY/` and the monthly `MM_sched.htm` pages; BEA `bea.gov/news/schedule` plus the BEA release archives per release; Census `calendar-listview.html` per year and `retail/release_schedule.html`); (2) parse to (kind, ET date, ET time, refPeriod, sourceURL); (3) **cross-check** each date with a second independent source, St. Louis Fed ALFRED/FRED release calendars (`fred.stlouisfed.org/releases/calendar?rid=<id>&y=<yyyy>`, e.g. rid 9 = Advance Retail Sales) and, for FOMC, the statement press-release URL (`newsevents/pressreleases/monetaryYYYYMMDDa.htm`); (3b) **first-publication check:** for each year and source, fetch the earliest Wayback capture of the annual schedule published before the year starts, plus captures through the year. Any instant that differs from today's page without a corrections row is reported as a silent reschedule. Its `announcedEt` is the first capture showing the new date, an upper bound and therefore conservative; (4) write the `// <event-table>` region and `tools/m-event/out/events_<from>_<to>.csv` (a human-readable copy); (5) print a disagreement report and refuse to write if any (kind, refPeriod) has two dates without a matching corrections row. (6) Store the raw fetched pages (or capture URLs with timestamps) under `tools/m-event/raw/` so the build is reproducible (page SHAs alone cannot be rebuilt once the pages change). (7) Resolve every remaining **VERIFY** in this spec (list in §12.2) and print each with its source. **No date is typed by hand or taken from a commercial calendar.**
- **EV-4.6 Coverage.** At least **2016-01-01 → 2027-12-31**, which covers the 1m window W-M (Jun/Jul 2016 →) and the tick window W-T (Jul 2024 →) with margin, plus the 2027 schedules the Fed and the agencies have already published (the Fed page lists 2027 meetings; BLS and Census publish next year's schedule late in the year: **VERIFY** the 2027 BLS/BEA availability at build time). `Configure()` journals `EVENT coverage(<kind>: first..last)` and returns an error if the chart's first bar is before the coverage start of an enabled kind (`EventConfig.allowPartialCoverage = false` by default). Coverage decided (Q2): 2016–2027 now, designed to extend back to 2000. An extension requires EV-5.6 (the Oct 2013 lapse, the 2001/2008 intermeeting FOMC actions), the pre-2013 14:15 ET FOMC statement time (EV-1.1) and the pre-2007 TZ check (EV-3.5).
- **EV-4.7 Year rollover live.** Outside coverage (e.g. 2028 before the table update) table kinds are **absent**, never guessed. Each year the engine is asked for, a Warning `EVENT <year> table kinds missing: <list>` is logged once. Rule kinds still generate.
- **EV-4.8 Table update procedure.** Re-run the script (late each year, and after any agency notice), commit, run `tests/EventTests`. The script's report goes in the PR body.

## 5. Backtest honesty: known-in-advance only

- **EV-5.1 `knownSinceUtc`.** A pre-event window or `MinutesTo` value at time *t* may use a record only if `t ≥ knownSinceUtc`. Annual schedules (Fed, BLS, BEA, Census, ISM, EIA) are published months ahead, so their rows get `MinValue`. This holds only for instants that match the schedule's first-publication capture (EV-4.5 step 3b). Instants that moved after first publication get `knownSinceUtc` = the first capture showing the move. A year with no capture before Jan 1 gets `knownSinceUtc` = its earliest capture, journaled as `EVENT knownSince capture-bound <source> <year>`.
- **EV-5.2 Unscheduled = known only at the instant.** A record flagged `Unscheduled` has `knownSinceUtc = announcedEt` (or `utc` when there was no notice). It is **excluded** from `NextEvent`, `MinutesTo` and pre-event windows before then. It is **included** in `EventsOn`, `PrevEvent`, `MinutesSince` and post-event windows from its instant (it happened; a post-event no-trade rule may honestly react to it).
- **EV-5.3 Rescheduled and canceled.** For a lapse in appropriations, every release scheduled inside the lapse gets `canceledSinceUtc` = the lapse start (00:01 ET of the first unfunded day; agency contingency plans are public), and its replacement instant gets `knownSinceUtc` = the earliest verifiable publication of the revised date (upper bound). For other reschedules, `canceledSinceUtc` = `knownSinceUtc` of the new instant = the announcement. A `Canceled` row with no replacement (e.g. Oct 2025 CPI) behaves the same way with no new instant. Before `canceledSinceUtc` the original instant is a normal known-in-advance record. Unscheduled FOMC is known at its instant (EV-5.2).
- **EV-5.4 Roll.** `RollWeek` is a schedule (known in advance). The **actual** `@ES` splice day is data and comes only from `rollOn(1)`. `IsRollDay` reports the splice as it is detected (same bar, no lookahead). `IsRollWeek` reports the CME rule. They can differ. Q3 (decided): do not wait for live; the build plan tabulates `rollOn(1)` splice dates over 2016–2024 history against the date-ranged CME rule (EV-1.21) and journals the weekday distribution (§10 step 7).

## 6. API

**Classes and files.** `_EventCalendar.Function.CS`: `EventConfig`, `EEventKind`, `EEventTier`, `EEventFlags`, `EEventClassMask`, `EventRec`, `EventDay`, the static `Rules` (regions), and the `internal sealed class _EventCalendar`. Host code goes in `_CustomSignal`, next to M-DAILY / G-R.

- **EV-6.1 Config** (protected, no `[Input]`; set in a derived ctor or `Create()`):
```csharp
public sealed class EventConfig {
    public bool enabled = false;
    public EEventClassMask classes = EEventClassMask.Macro | EEventClassMask.Calendar;
    public EEventTier minTier = EEventTier.T3;          // records below are dropped at build
    public Dictionary<EEventKind, EEventTier> tierOverride = new Dictionary<EEventKind, EEventTier>();
    public string csvPath = "";                           // EV-4.4
    public bool allowPartialCoverage = false;             // EV-4.6
    public int blackoutPreMin = 0, blackoutPostMin = 0;   // EV-6.7; 0/0 = no blackout
    public EEventTier blackoutTier = EEventTier.T1;
    public bool blackoutFlatten = false;                  // EV-6.7
    public bool publish = false;                          // EV-7
    public string Validate(); public string Canon();
}
```
- **EV-6.2 Host members on `_CustomSignal`:** `protected EventConfig EventConfig { get; } = new EventConfig();`, `private _EventCalendar m_event;`, `private bool m_eventQueryWarned;`, `internal _EventCalendar EventCalendar { get; }` (Warning once when null), `startEvent()` in `StartCalc` after `startDaily()`/`startRegime()` (`journal = engineSink(ETraceLevel.Journal)`, `warnOnce = engineSink(ETraceLevel.Warning)`, `Configure()` errors throw `ArgumentException`), and `stepEvent()` in the engine step after `stepRegime()` (it only feeds the bar UTC interval and the roll flag; closed bars only, idempotent per `CurrentBar`).
- **EV-6.3 Engine time input.** `stepEvent` computes `nowUtc` (bar close) and `barOpenUtc` once per bar (EV-3.3) and passes them in. The engine never reads a clock (`DateTime.Now` is forbidden, so live and backtest behave the same).
- **EV-6.4 `IList<EventRec> EventsOn(DateTime tradingDay, EEventClassMask mask = All)`.** Returns **as-of** records for that Globex trade date (`knownSinceUtc ≤` current bar close; Canceled excluded once `canceledSinceUtc ≤` the bar close), sorted by time. `EventsOnExPost(day, mask, includeCanceled)` is the research-only variant. `EventsInRange(fromDay, toDay)` (as-of) and `EventsInRangeExPost` do the same for ranges (weekly bars).
- **EV-6.5 `EventDay Classify(DateTime tradingDay)`.** A struct: `maxTier` (macro), `kindsMask` (ulong), `hasFomc`, `hasSep`, `isHalfDay`, `isRollWeek`, `isQuarterlyExpiry`, `isOpex`, `isRebalance`, `firstReleaseEt` (TimeSpan?). Used as a regime or filter. **As-of rule:** only records with `knownSinceUtc ≤ asOfUtc` count (default `asOfUtc` = the session's 18:00 ET open), so an emergency FOMC never makes its own day an "event day" ex ante (EV-5.2). `ClassifyExPost(day)` includes them and is for research labelling only (§8).
- **EV-6.6 Next / previous.** `bool NextEvent(DateTime nowUtc, EEventTier minTier, EEventClassMask mask, out EventRec e)` (strictly after `nowUtc`, honouring `knownSinceUtc` and Canceled), `bool PrevEvent(...)` (at or before `nowUtc`, including Unscheduled), `double MinutesTo(minTier, mask)` and `double MinutesSince(minTier, mask)` for the current bar (`NaN` when there is none in the cache horizon; the horizon is y+1). Spans (`RollWeek`) are reported by `InSpan(kind)`, not by Next/Prev.
- **EV-6.7 `bool IsInWindow(EEventTier minTier, int preMin, int postMin, EEventClassMask mask = Macro)`.** True when the current bar interval `[barOpenUtc, barCloseUtc)` overlaps the half-open `[utc − pre, utc + post)` of any qualifying event (pre-side only for known-in-advance records, post-side for all, EV-5.2). Convenience: `protected bool EventBlackout` = `IsInWindow(blackoutTier, blackoutPreMin, blackoutPostMin)`. **The base does not block orders.** Consumers decide. `blackoutFlatten` only exposes `EventFlattenNow` (true on the first bar entering a blackout) for a consumer's exit code. Wiring it into `_CustomSignal`'s order path is out of scope (Q5, decided: no entry blocking in rev 2).
- **EV-6.8 Roll helpers.** `bool IsRollWeek` (EV-1.21 rule), `bool IsRollDay` (the actual `rollOn(1)` splice seen today), `int SessionsToExpiry` (Globex sessions until the next quarterly expiry, from `_CmeHolidays`).
- **EV-6.9 Neutral values when disabled:** `EventsOn` empty, `Classify` default (`maxTier = None`), `MinutesTo/Since = NaN`, `IsInWindow = false`, `EventBlackout = false`, plus one Warning.
- **EV-6.10 Journal lines** (Journal level, bar-time stamped): on configure, `EVENT created classes(..) minTier(..) csv(<path> rows n sha ..) coverage(..)`; once per trading day with events, `EVENT day <yyyy-MM-dd> tier(<max>) kinds(<list>) firstRelease(<ET>)`; on blackout enter and leave, `EVENT blackout on|off <kind> <ET time> pre(..) post(..)`. when `EventConfig.enabled`, `CS-1` trade-journal rows get two extra columns, `evtDayTier` and `evtMinSince` (NaN-safe; schema unchanged for runs with M-EVENT off; the RUN line records the schema), so Gate 3 event studies can be split later without rerunning (Q8).
- **EV-6.11 Performance.** Classify and window queries are O(log n) with no allocation. `EventsOn` returns a cached read-only list per day.
- **EV-6.12 NewsBar AVWAP anchor hook (Q6).** `bool LastT1Instant(DateTime nowUtc, out DateTime etInstant)` returns the most recent T1 macro instant at or before `nowUtc` (post-event only, as `PrevEvent`; never a future instant). `EAvwapAnchor.NewsBar` will anchor at the bar containing that instant (EV-3.3). Calendar-only: no headlines. Rev 2 specifies and tests the hook (EV-8.12); wiring it into the AVWAP engine is rev 1.1.

- **EV-8.3 DST.** (a) An 08:30 ET event on the Monday after spring-forward (2026-03-09) and fall-back (2026-11-02) maps to 13:30 / 12:30 UTC after the change, and the minute before it is pre-event, for chart zones Eastern, Central (Exchange), UTC, and a no-DST local zone (South Africa Standard Time) and an EU zone (W. Europe) during the US/EU mismatch weeks (e.g. 2026-03-09 … 03-27 and 2026-10-26 … 10-30). (b) `MinutesTo` across the DST weekend equals the UTC difference (EV-3.4 example). (c) A table row at 02:30 ET on a spring-forward Sunday fails `Configure()`.

## 9. First research uses (hypotheses only, no statistics)

These are pre-registration candidates. Nothing here is a finding (catalogue §2.6 and Gate 3 rules).

**Pre-registration clause.** Before any EV-9 run, register in the PR:
- (a) dev window 2016-07 → 2024-12; holdout 2025+ untouched (catalogue §2.0.1);
- (b) metric and test;
- (c) matched control days (same weekday, same ATR tercile, no macro event, ±4 weeks);
- (d) the cell list, with expected n (T1 days ≈ 32/yr → ≈ 270 dev; FOMC ≈ 68; half days ≈ 25 → descriptive only, since n < 30);
- (e) Holm correction across all EV-9 cells;
- (f) a kill rule;
- (g) the configs charged to the trial budget.

- **EV-9.1 Event-day split for the Gate 0 canaries.** Re-read VW-08 (+ A2-24 i–iii, DV-10), A2-53, DV-01 and PS-03 outcomes split by `Classify` as-of: {T1 day, T2-only day, no macro event}, with FOMC days and half days as their own cells. *Hypothesis:* the canaries stay ≈ 0 or negative in every cell. A canary that is positive only on non-event days points to an event-day cost or fill artefact, not an edge. The split is a diagnostic. It must not be used to rescue a canary (that would be a new config charged to the trial budget). *Metric:* net PF and mean net R per cell, block bootstrap 500/5; cells with n < 30 are report-only; a positive cell triggers a fill or cost audit, never a config.
- **EV-9.2 No-trade windows.** *Hypothesis:* a blackout of [−5, +10] min around T1 releases (Dale's rule in `trading-ideas-dale-video.md`) lowers slippage-stressed loss (A2-40/A2-59 cost model) without lowering the mean net R of level ideas. It is tested as a layer (L-step ablation) on host events. Window sizes are fixed in advance: {[−5, +10], [−15, +30], FOMC [−30, +90]}, at most 3 configs. *Metric:* p90 adverse slippage and mean net R of host events with versus without the blackout; host = the PS-01 / PS-08 / PS-24 event sets; kill if mean net R falls by more than 1 SE or slippage is not lower at Holm p < 0.05; 3 configs charged.
- **EV-9.3 Opening-range ideas on 08:30 days.** *Hypothesis:* on days with a T1 08:30 release the overnight range and the 09:30 IB behave differently (the release lands before RTH), so IB-based ideas should report results split by `firstReleaseEt` ∈ {08:30, 10:00, 14:00, none}. *Metric:* ON range / ATR20d and IB width / ATR20d by `firstReleaseEt` cell versus matched control days; descriptive, no trade; Holm across the 4 cells.
- **EV-9.4 Regime bucket.** *Hypothesis:* `maxTier` adds information to G-R's `AtrTercile` baseline as a stratifier. It is a prior or bucket only, never an entry trigger (same use rule as G-R, P3 §3.3). *Metric:* incremental log-loss or R² of `maxTier` over `AtrTercile` for next-session |return| and range, dev window only; kill if the gain is ≤ 0 on the walk-forward folds.
- **EV-9.5 Roll and expiry weeks.** *Hypothesis:* level studies (A2-33) and VWAP canaries behave differently in roll weeks and on quarterly expiry and rebalance Fridays, so those sessions are reported as separate cells rather than pooled. *Cells:* roll week (rule), splice day, quarterly expiry Friday, rebalance Friday versus the rest; A2-33 edge and canary PF reported per cell; descriptive.
- **EV-9.6 A2 consumers.** A2-01/A2-05 (event AVWAP anchors CPI/NFP/FOMC release bar), A2-21 (FOMC 14:00 second leg, pooled with CPI/NFP), A2-35 (re-formation VA at T+20) and A2-20 (EIA 10:30, CL) read instants from M-EVENT post-event only (`PrevEvent` / `MinutesSince` / `LastT1Instant`).

## 14. EV-4.6b Per-kind, per-day fail-closed coverage

*Amendment, approved by Ettienne Hugo 2026-10-23; reviewed and agreed by Analyst 2.*

- **Scope.** Coverage is evaluated per event kind and per day, not per calendar.
- **Tri-state.** A day inside a coverage hole for a kind returns `Unknown` (`Event` / `NoEvent` / `Unknown`).
- **Blocking.** `Unknown` blocks only when that kind is in the consumer's `EEventClassMask` **and** `allowPartialCoverage = false`; otherwise it is treated as `NoEvent`.
- **Journal.** Holes are journaled once at start and once per affected day with tag `COVGAP` (via `ETraceLevel.Journal`).
- **Reporting.** Report, per kind and per test window, the share of days blocked due to `Unknown`; flag any window above 5%.
- **Engine-wide disable.** Applies only when the table file is missing or its hash mismatches. This replaces the previous whole-calendar-off default for gaps (R2.1-h).
- **Required tests.** (1) a hole day returns `Unknown`; (2) it blocks under `allowPartialCoverage = false`; (3) it is treated as no-event under `true`; (4) end-of-coverage (e.g. JOLTS after 2026-12) behaves the same as a hole; (5) a hole day for a kind NOT in the consumer's `EEventClassMask` does not block, even under `allowPartialCoverage = false`.
- **Tier filter (added 2026-10-23, reviewed by Analyst 2).** When a query passes a minimum tier, an `Unknown` kind whose effective tier is below that minimum does not block, since it could never have opened the window. The effective tier is resolved from the same config the query runs under (`tierOverride` applied first, then compared), not from the table default. Such a day still gets its `COVGAP` journal entry but does not count toward the >5% Unknown-blocked share. Required test (6): an `Unknown` hole for a kind below the query's minimum tier does not block under `allowPartialCoverage = false`, and the same hole at or above the minimum does.
