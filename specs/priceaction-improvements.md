# PriceAction library — code review and improvement list

Repo: `github.com/ettiennehugo/PriceAction` (read-only clone `/workspace/PriceAction`, HEAD `a45b673`). Files: `PriceAction/PriceActionAnalysis.cs` (1388 lines), `PriceActionBar.cs`, `PriceActionState.cs`, `FractalPivotState.cs`, `PriceActionAnalysisState.cs`. Target .NET Framework 4.8 class library, no test project. Nothing was pushed or edited. Reviewed 2026-10-21 (ET). Line numbers refer to `PriceActionAnalysis.cs` unless stated.

Priority: **H** = wrong results or repainting that can leak into a backtest; **M** = performance/robustness/API problems that will bite in MultiCharts use; **L** = clarity/hygiene.

## High

| # | Where | Problem | Suggested fix |
|---|---|---|---|
| H1 | `FractalLayer.analyseHighs/analyseLows` l.1300–1360 | When a pivot flag *changes*, the bar is written into `m_pivotHigh/m_pivotLow` **even when the new state is false** (`if (changed) m_pivotHigh[ts] = currentMin1`). A forming bar that first makes `currentMin1` a pivot and then (next tick, higher high) un-makes it leaves a **non-pivot in the pivot list**. HH/LH/double-top (l.863–1049), higher layers (`Analyse(previousLayer)` uses the last 3 entries) and breakout (l.831/844) then use a bar that is not a pivot. | Add when true, `Remove(ts)` when it becomes false; or, better, evaluate pivots only on closed bars (H3). |
| H2 | `Analyse` l.335–355 | `PriceActionBar.index = m_bars.Count + 1`; once the 500-bar window is full the count is constant, so **every new bar gets the same index** (`Size+1`). Any consumer using `index` (commit a3b3e99) is wrong after 500 bars. | Keep a monotonically increasing `m_barCounter`. |
| H3 | `Analyse` l.357–379 + all detectors | Repainting by design: re-analysing the same timestamp (forming bar / IOG) re-runs every detector and **rewrites the prior bar's pivot state** (`currentMin1` is judged against a still-forming `currentBar`). Pivot/HH/LL flags appear and disappear intrabar; `ChangedBars` reports bars in the past. A strategy reading flags intrabar has lookahead relative to a backtest on closed bars. | Add `Analyse(..., bool barClosed)`; update provisional candle flags on every tick but commit pivots/labels only when `barClosed`. Expose `confirmTimestamp` for each pivot. |
| H4 | `renumberPivots` l.1056–1226 | (a) **Asymmetric start search**: lows break on `timestamp < m_oldestPivotDetected` (l.1099), highs on `timestamp >= m_oldestPivotDetected` (l.1102) — the high loop starts at the newest pivot while the low loop starts at the one before the oldest, so high/low counters are renumbered over different ranges. (b) Inner loops use `nextLayerPivotIndex > 0` (l.1120, 1136, 1180, 1196) so **index 0 of the next layer is never checked**. (c) The whole routine rewrites counters of historical pivots (repaint). | Make both searches `>= oldest` (or both `<`, deliberately), loop `>= 0`; long term replace counters by immutable per-pivot sequence numbers assigned at confirmation (no rewrite). Unit tests around a 3-layer sequence. |
| H5 | `detectDoubleTop/Bottom` l.863–999 | Relabels the **earlier** pivot (`doubleTop = true; higherHigh = false; lowerHigh = false`, l.895–897, 991–993): history changes after the fact (repaint) and the earlier HH/LH label is lost. Also `m_currentMin1.state.doubleTop` is overwritten each loop iteration, and a `new List<PriceActionBar>()` is allocated per pivot (l.874, 970). | Flag only the new pivot (`isEqual`/`doubleTop` with a reference to the matched pivot timestamp); keep HH/LH labels; no allocation. (Our `_SwingEngine` rev 2 already does this.) |
| H6 | `detectBreakout` l.808–856 | l.817 sets `breakout = strong` and only overwrites it when `m_layers.Count > 2`. With ≤ 2 layers (**the default for most uses**), **every strong bar is reported as a breakout**. With > 2 layers, layers 0 and 1 are never checked (`index > 1`), contradicting the comment "at least two fractal layers". It compares `high` (not close) with the last pivot, even if that pivot was already broken before. | Initialise `breakout = false`; check layers `>= 1` (or a configurable minimum); use close beyond the last *unbroken* pivot; mark the pivot as broken. |
| H7 | `Clear()` l.313–319 | Resets bars and layers but not `m_currentBar/m_currentMin1/m_currentMin2`, ATR, volume stats, `m_analysisState`. After `Clear()` the next bars are compared with **stale previous bars** (engulfing, inside, reversal use `m_currentMin1`). | Reset every field (factor a private `resetState()` shared with the ctor). |
| H8 | `Size` setter l.76–82 | Trims `m_bars` but **not the layer pivot lists**, unlike `Analyse` l.351–355 which calls `layer.Remove`. Layers keep references to evicted bars. | Reuse the same eviction routine. |
| H9 | `Analyse` l.335–353 | A timestamp **older** than the current bar that is not in the list is treated as a *new current bar* (it is inserted in sorted order but becomes `m_currentBar`, and `currentMin1/Min2` are shifted). Also two bars with the **same timestamp** (tick/seconds charts, MC bars stamped to the second) collide and overwrite each other. | Reject out-of-order input (throw/return false) and key bars by a caller-supplied bar number (MC `CurrentBar`), not `DateTime`. |

## Medium

| # | Where | Problem | Suggested fix |
|---|---|---|---|
| M1 | `updateIndicators` l.449–530 | Per bar: allocates `double[atrLength]`, recomputes ATR over 20 bars and volume mean/σ over 20 bars (two passes, `Math.Pow`). O(n) per tick with IOG. | O(1) rolling sums (ring buffer for TR and volume, Σv and Σv²); no allocation. |
| M2 | `m_bars` `SortedList<DateTime,…>` + `RemoveAt(0)` l.353–354 | `RemoveAt(0)` shifts the whole 500-element array every bar; each `PriceActionBar` allocates a `PriceActionState` + `List<FractalPivotState>` + one object per layer (`PriceActionState.cs` ctor). GC pressure in long backtests. | Circular buffer of structs indexed by bar number; pivot lists as small ring buffers; window only as large as the longest lookback (≈ max(atrLength, volumeLength) + layers×3 pivots), not 500 bars. |
| M3 | Roll handling (none) | On unadjusted continuous futures (`@ES`) the roll splice inflates TR → ATR for 20 bars → all `m_size*` thresholds (doji, close, strong, ε), and creates fake pivots/HH/LL across the gap. | Add `NotifyRoll(timestamp)` (or a `bool rollBar` argument): skip the splice TR, reset ATR ring, clear pivots/labels from before the roll. |
| M4 | Silent setters: `AtrLength` l.196–199, `FactorDoji/Close/Strong/Epsilon` l.220–270 | Invalid values are **ignored silently** (`if (value > 0 && value < m_size) m_atrLength = value;`), while `Size`/`VolumeLength` throw. Changing `AtrLength` after bars exist does not recompute anything. `VolumeLength > Size` is never checked. | Validate consistently with `ArgumentOutOfRangeException`; make settings immutable after first `Analyse` (options object passed to the ctor). |
| M5 | HH/LH/HL/LL l.909–1049 | Labels only fire when `|Δ| > m_sizeClose`; double top needs `|Δ| < m_sizeClose`. A pivot with Δ exactly equal gets neither; a pivot near-equal to the *previous* pivot but not to the matched older one gets no HH/LH label at all. Only layer 0 gets labels; higher layers never do. | Always assign HH/LH (ties documented) and a separate equal flag; compute labels per layer. |
| M6 | Strict fractal comparator `isHigh/isLow` l.1365–1385 | `>`/`<`: flat tops/bottoms (two adjacent equal highs) **never** form a pivot, common on tick-rounded futures prices. | Option `PivotTieRule { Strict, LeftInclusive }` (e.g. `mid >= left && mid > right`). |
| M7 | Candle rules l.620–800 | `highPin` means body near the **high** (a hammer, long lower tail) — name suggests the opposite; magic `0.3333333334`. Bullish reversal rule 2 accepts a zero lower tail (`lowerTail < barHeight/2`), not "one-third to one-half". Bearish rule 1 checks `close < prior open`, not "well below prior close". | Rename (`bodyAtHigh/bodyAtLow` or `hammer/shootingStar`), named constants, implement rule 2 as `barHeight/3 ≤ tail ≤ barHeight/2`, document rule deviations from Brooks p.89. |
| M8 | Public mutable API | `Bars`, `ChangedBars`, `CurrentBar` expose internal `SortedList` and mutable `PriceActionBar`/state objects; callers can corrupt state. Public fields everywhere (`PriceActionBar`, `PriceActionState`). | Return `IReadOnlyList`/read-only views or immutable snapshots; properties instead of fields. |
| M9 | Testability | No test project; logic depends on private state and implicit detector order ("NOTE: assumes doji detection before…", l.714, 812). | Add an xUnit/NUnit project with CSV fixtures (ES 1-min sessions incl. a roll day, flat tops, gaps); golden-file tests for pivots/labels; property tests "closed-bar replay == tick replay" (repaint check). Make detectors pure static functions `(bar, prev, prev2, atr) → flags`. |
| M10 | MultiCharts integration | Standalone net48 DLL: MC .NET studies must reference it (GAC/`Bin` copy) — awkward to deploy and version, and MC recompiles studies from source. Not aware of `Bars.Status`, `CurrentBar`, sessions or data streams. | Either ship as source file(s) in the MC studies project (`_PriceAction*.Function.CS`, VPB-9 helper convention, as done for `_SwingEngine`) or provide a thin MC adapter: `Step(IInstrument bars)` that maps `CurrentBar`, `Status == Close`, `LastBarInSession`. |

## Suggested order of work

1. H1, H2, H6, H7, H8, H9 — small, local bug fixes (each < 20 lines) with a regression test each.
2. H3/H4/H5 — closed-bar commit model and immutable pivots (removes repaint); this is the semantic change, so version it (2.0).
3. M1–M3 performance and roll handling; M9 test harness alongside.
4. API (M4, M8, M10) and naming (M7).

The `_SwingEngine` draft in `/workspace/MultiCharts.Net/_SwingEngine.Function.CS` already embodies H1, H3, H4, H5, M1, M2, M3 and M6-doc for the swing part; the candle-pattern part of PriceAction has no MC engine yet.
